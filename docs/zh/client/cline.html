Cline 搭配免费 LLM API

Cline 需要的配置由清单直接生成，另附真正能配合它工作的免费额度。

Cline 需要什么

Cline 自带一种 OpenAI Compatible 服务商类型，只需要三个值：base URL、API key、model id。

  1. base URL 是提供 /chat/completions 的那个根地址。多数服务商在文档里给出的写法已经包含 /v1 后缀。
  2. model id 要用服务商那边确切的 id，不是展示名；Cline 会原样透传。
  3. 模型必须把工具调用做得足够好，能吐出合法的 diff。这才是真正的筛选条件：小的免费模型经常返回格式坏掉的编辑，Cline 表现为反复 apply 失败，而不是 API 报错。
  4. 这些值要在 Cline 设置面板里手工输入。本项目不读也不写 VS Code 扩展的存储。

这条命令会生成什么文件

运行 npx free-llm-api setup cline 会写出 SETUP.md。它是一份对照检查清单而不是配置文件，因为这些值要手工填进设置面板，而本项目不会去写别的工具的凭据存储。下面是按 GroqCloud 填好的样子：

# Cline setup

This project does not modify VS Code or Cline extension storage.

1. Open Cline settings and choose **OpenAI Compatible** as the API Provider.
2. Set **Base URL** to `https://api.groq.com/openai/v1`.
3. Paste the key held in `GROQ_API_KEY` into Cline's API Key field manually.
4. Set **Model ID** to `openai/gpt-oss-120b`, save, and send a small test message.

那个文件里没有 key。值在运行时从 GROQ_API_KEY 读取——就这一个习惯，从结构上保证凭据进不了仓库。

用免费额度该有什么预期

Plan 模式和 Act 模式发出的 prompt 体积差别很大，所以一家能顺利做规划的服务商，仍可能在一个大 diff 上失败。如果 API 一直返回 200 而编辑总是失败，瓶颈是模型而不是额度。

在怪客户端之前，先验 key 本身：浏览器检测页能把「凭据被拒」「被限流」和「端点根本没起来」这三种情况分开，而它们的解法各不相同。

Cursor 搭配免费 LLM API

Cursor 需要的配置由清单直接生成，另附真正能配合它工作的免费额度。

Cursor 需要什么

Cursor 在设置面板里接受自定义的 OpenAI base URL 和 key，这也是把它指向免费额度的唯一受支持方式。

  1. 这些值要手工填进 Cursor Settings > Models。本项目只生成一份对照指南，绝不碰 Cursor 的设置文件或它的凭据存储。
  2. 覆盖 OpenAI base URL 会连内置模型一起改掉，所以这是一个全局开关，而不是按请求生效的开关。
  3. 自定义 key 只对受支持的对话模型生效。Tab 补全之类的功能仍然走 Cursor 自己的模型。
  4. 模型必须按服务商那边确切的 id 添加并通过验证，否则 Cursor 会一直把请求发往一个服务商并不提供的名字。

这条命令会生成什么文件

运行 npx free-llm-api setup cursor 会写出 SETUP.md。它是一份对照检查清单而不是配置文件，因为这些值要手工填进设置面板，而本项目不会去写别的工具的凭据存储。下面是按 GroqCloud 填好的样子：

# Cursor setup

This project does not modify Cursor settings or its credential storage.

1. Open **Cursor Settings > Models**.
2. Add your key from the `GROQ_API_KEY` environment variable to the OpenAI API key field manually.
3. Set **Override OpenAI Base URL** to `https://api.groq.com/openai/v1`.
4. Add or select the model `openai/gpt-oss-120b`, then click **Verify**.

Changing the OpenAI Base URL can affect built-in models. Custom API keys apply only to supported chat models; features such as Tab Completion continue to use Cursor's built-in models.

那个文件里没有 key。值在运行时从 GROQ_API_KEY 读取——就这一个习惯，从结构上保证凭据进不了仓库。

用免费额度该有什么预期

因为覆盖是全局的，一旦免费额度把你限流，整个编辑器都会跟着受影响。把内置配置留在一键可切回的位置。

在怪客户端之前，先验 key 本身：浏览器检测页能把「凭据被拒」「被限流」和「端点根本没起来」这三种情况分开，而它们的解法各不相同。

Claude Code 搭配免费 LLM API

Claude Code 需要的配置由清单直接生成，另附真正能配合它工作的免费额度。

Claude Code 需要什么

Claude Code 讲的是 Anthropic Messages API，而本清单里几乎每一个免费额度讲的都是 OpenAI chat completions API。

  1. ANTHROPIC_BASE_URL 必须指向一个接受 Anthropic 格式请求的端点。Claude Code 会自己拼接 API 路径，所以这个值是网关根地址，不带 /v1 后缀。
  2. ANTHROPIC_AUTH_TOKEN 持有 key，在启动时从环境变量读取。
  3. 你写的模型名必须在那个端点上真实存在。写错的 model id 会由服务商返回 404，而不是由 Claude Code 报错。
  4. 真正让免费 Claude Code 配置失败的通常是这层协议不匹配，而不是 key。要么在兼容 OpenAI 的免费端点前面加一个做协议转换的路由，要么直接用一个本身就讲 Anthropic 的网关。

这条命令会生成什么文件

运行 npx free-llm-api setup claude-code 会写出 run-claude-code.sh。它由清单生成，所以 base URL 和 model id 都是服务商文档里的原值，不用你再去翻。下面是按 GroqCloud 填好的样子：

#!/usr/bin/env sh
set -eu

: "${GROQ_API_KEY:?Set GROQ_API_KEY before running Claude Code}"
ANTHROPIC_BASE_URL='https://api.groq.com/openai/v1' \
ANTHROPIC_AUTH_TOKEN="$GROQ_API_KEY" \
exec claude "$@"

那个文件里没有 key。值在运行时从 GROQ_API_KEY 读取——就这一个习惯，从结构上保证凭据进不了仓库。

哪些免费额度适合 Claude Code

本清单里只有 1 条不兼容 OpenAI 协议，所以没法给 Claude Code 列一张开箱即用的免费额度表。现实的路子有两条：本地起一个做协议转换的路由、由它持有你自己的服务商 key，或者用一个本身就按 Anthropic 格式应答的网关。

用免费额度该有什么预期

Agent 会话消耗每日额度的速度远快于聊天，因为每一次工具调用都是又一段长 prompt。429 只告诉你那一次请求被限流，除非服务商返回了 reset 头，否则它不说明还剩多少额度。

在怪客户端之前，先验 key 本身：浏览器检测页能把「凭据被拒」「被限流」和「端点根本没起来」这三种情况分开，而它们的解法各不相同。
